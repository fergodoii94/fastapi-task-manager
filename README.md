# Task Manager API

A portfolio backend project built with Python 3.12, FastAPI, SQLAlchemy 2.0, PostgreSQL and Alembic. It demonstrates REST API design, persistence, validation, pagination, dependency injection, database migrations, automated tests and containerization.

[![CI](https://github.com/fergodoii94/fastapi-task-manager/actions/workflows/ci-cd.yml/badge.svg)](https://github.com/fergodoii94/fastapi-task-manager/actions/workflows/ci-cd.yml)

## Implemented features

- CRUD endpoints for tasks with typed request and response schemas.
- SQLAlchemy 2.0 persistence; PostgreSQL with Docker Compose and SQLite by default for local development/tests.
- Pagination and filtering by task status.
- Input validation for titles, status, priority and partial updates.
- Alembic migration history, including the initial tasks-table migration.
- Integration tests using isolated in-memory SQLite.
- Docker image runs as a non-root user.
- GitHub Actions workflow configured to run Ruff and Pytest.
- Interactive OpenAPI documentation at `/docs`.

## Architecture

- `src/routes/`: HTTP endpoints and dependency injection.
- `src/services.py`: persistence operations.
- `src/models.py`: SQLAlchemy ORM models.
- `src/schemas.py`: Pydantic request/response contracts.
- `src/database.py`: engine, session factory and declarative base.
- `alembic/`: versioned database migrations.

## Run locally

Requires Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
alembic upgrade head
uvicorn src.main:app --reload
```

The default database is SQLite. Set `DATABASE_URL` in `.env` to a PostgreSQL SQLAlchemy URL to use PostgreSQL. Apply new schema changes through Alembic migrations; do not rely on `create_all` in application startup.

## Run with Docker Compose

```bash
docker compose up --build
```

The API container applies migrations before starting Uvicorn.

- API: http://localhost:8000
- OpenAPI: http://localhost:8000/docs
- Health: http://localhost:8000/health

The credentials in `docker-compose.yml` are for local development only. Replace them and use a secret manager/environment-specific configuration before any deployment.

## API endpoints

Base path: `/api/v1`

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/tasks` | Create task (201) |
| GET | `/tasks?page=1&page_size=10&status=pending` | Paginated list and optional status filter |
| GET | `/tasks/{id}` | Retrieve task |
| PATCH | `/tasks/{id}` | Partial update |
| DELETE | `/tasks/{id}` | Delete task (204) |

Statuses: `pending`, `in_progress`, `completed`, `archived`. Priority ranges from 1 to 5. Titles are trimmed, required and limited to 160 characters.

## Database migrations

Create a new migration after changing ORM models:

```bash
alembic revision --autogenerate -m "describe schema change"
alembic upgrade head
```

Review autogenerated migration files before applying them. To inspect the current revision, run `alembic current`.

## Quality checks

```bash
ruff check src tests alembic
pytest
```

Tests use isolated SQLite and do not require PostgreSQL. The GitHub Actions workflow is configured to run these checks on pushes and pull requests; see the Actions tab for the actual result of each run.

## Current scope and limitations

This is a learning/portfolio API, not a production-ready multi-user service. Authentication/authorization, rate limiting, observability, deployment secrets management and production migration operations are not implemented. Do not expose it publicly with real user data until those controls are added and reviewed.

## Configuration

- `DATABASE_URL`: defaults to `sqlite:///./task_manager.db`.
- `APP_NAME`: defaults to `Task Manager API`.
- `API_V1_PREFIX`: defaults to `/api/v1`.

Never commit production credentials.
